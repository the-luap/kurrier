## Overview

Kurrier exposes a HTTP+JSON API for reading mailboxes and messages, sending email,
managing identities, and managing webhooks.

All endpoints live under the Kurrier namespace:

```text
https://your-domain.com/api/kurrier
```

For Paul’s local instance the base URL is:

```text
https://kurrier.local.nothaft.cloud/api/kurrier
```

The base route is a discovery endpoint:

```http
GET /api/kurrier
```

It returns the API name, version, supported scopes, and the currently available
routes.

## API keys

Create and manage API keys in the Kurrier dashboard:

```text
/dashboard/platform/api-keys
```

Steps:

1. Open **Dashboard → Platform → API Keys**.
2. Create an API key.
3. Select the scopes your integration needs.
4. Copy the key once and store it securely.

## Authentication

Every authenticated request must include the API key as a bearer token:

```http
Authorization: Bearer <api-key>
```

Example:

```bash
curl https://your-domain.com/api/kurrier/me \
  -H "Authorization: Bearer $KURRIER_API_KEY"
```

---

## Scopes

| Scope | Allows |
|-------|--------|
| `emails:receive` | Read mailboxes, mailbox overviews, threads, messages, identities, and webhooks. |
| `emails:send` | Compose new emails and reply to existing messages/threads. |

Use the smallest scope set needed by your integration. For OpenClaw/AI email
agents that need to read and answer mail, create a key with both `emails:receive`
and `emails:send`.

---

## Response envelope

Successful API responses use this shape:

```json
{
  "success": true,
  "data": {}
}
```

Errors use Nitro/H3’s JSON error format and include `statusCode`,
`statusMessage`, and `message`.
